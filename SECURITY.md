# Security Policy

## Reporting A Vulnerability

Report suspected security issues privately through GitHub Security Advisories
for `home-ops/librespeed-exporter`:

1. Open repository **Security** tab.
2. Select **Advisories** and **Report a vulnerability**.
3. Include affected version or image digest, impact, reproduction steps, and
   suggested mitigation when known.

Private vulnerability reporting must be enabled in repository settings for this
option to appear. Repository administrators must enable **Settings > Security >
Private vulnerability reporting**. If it is unavailable, do not disclose
details in a public issue; contact repository maintainers through an existing
private channel and request one. No security contact email is asserted here.

Please allow maintainers reasonable time to investigate and coordinate a fix
before public disclosure. Do not include real server credentials, private
endpoints, client IP addresses, or other personal data in reports unless
strictly necessary; redact them where possible.

## Scope And Response

Report vulnerabilities in exporter code, container build/runtime configuration,
release artifacts, or deployment examples. The project does not promise a
particular response SLA or that every report will result in a release. Published
container signatures and provenance, when available, establish artifact origin
claims and do not guarantee absence of vulnerabilities.
